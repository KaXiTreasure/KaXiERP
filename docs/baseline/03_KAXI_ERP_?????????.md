## 第1编｜KAXI_ERP_角色与权限矩阵

> 状态：项目基线草案  
> 适用版本：KAXI ERP V1.0

### 1. 权限设计原则

- 使用“用户—岗位—角色—权限”模型，一个用户可拥有多个角色。
- 系统管理员可以针对任何单独用户追加、限制或收回权限，不必为了一个人新建角色。
- 功能权限、数据范围权限、字段权限和审批权限分开控制。
- 默认拒绝，按最小权限授权。
- 查看价格不等于查看成本；创建单据不等于确认、作废或审批。
- 仓库、客户、供应商、渠道和公司主体均可作为数据范围。
- 高风险操作必须记录原因、操作人、审批人和前后值。
- 系统管理员负责技术配置，不默认拥有合同、成本、银行和客户隐私内容权限。
- 不允许通过直接修改数据库绕过业务单据和审批。

#### 1.1 用户级单独授权

系统支持在角色权限之外，为具体人员设置用户级权限例外：

```text
用户有效权限
= 岗位/角色权限
+ 用户级追加授权
- 用户级明确限制
```

- 系统管理员可以为任何人员单独开放功能、数据范围、字段、审批、导出、下载或分享权限。
- 也可以对某个用户单独禁止其角色原本拥有的权限。
- 单独授权可以设置永久或临时有效期，临时权限到期后自动失效。
- 授权时必须记录权限内容、数据范围、原因、授权人、生效时间和失效时间。
- 成本、银行、L4文件、财务红冲、超授信审批、库存调整和彻底删除等高风险权限，必须按公司规则增加复核或审批，系统管理员不能通过普通授权绕过既定业务审批。
- 系统管理员可以配置权限，但不因此自动获得被授权业务数据的查看权限。
- 所有新增、修改、复制、撤销和到期行为必须进入不可篡改的权限审计日志。
- 用户权限页面必须能展示“最终有效权限”及其来源，便于排查权限冲突。

### 5. 数据范围规则

权限可叠加以下范围：

- 公司主体
- 部门/团队
- 仓库/库区
- 销售渠道
- 贸易类型
- 国家/地区
- 客户/代理归属
- 供应商品类
- 商品分类/品牌/系列
- 单据创建人、负责人或协作人

示例：济南仓操作员只能操作济南仓；外贸业务员只能查看自己负责的海外客户，但被加入协作人的订单除外。

系统管理员可以为单个用户扩展或缩小上述数据范围，例如仅增加“上海仓库存查看”或“某个海外客户订单查看”，无需授予整个仓库或整个外贸团队权限。

### 6. 字段权限

| 字段组 | 默认可见角色 |
|---|---|
| 销售价与折扣 | 销售、外贸、代理、财务及管理层按范围 |
| 采购价 | 采购、财务、授权管理层 |
| 标准成本/实际成本 | 财务、授权管理层及指定商品/生产负责人 |
| 毛利 | 财务、管理层、授权销售主管 |
| 授信额度与欠款 | 销售负责人、财务、管理层；业务员仅看本人客户 |
| 银行账户与回单 | 财务及授权管理层 |
| 客户证件与隐私 | 相关销售、财务和授权管理人员 |
| 供应商银行信息 | 采购主管、财务 |
| 工艺和核心设计 | 商品、生产、质检及授权管理层 |

列表、导出和 API 必须遵守相同字段权限，不能只在页面上隐藏。

### 7. 审批规则基线

以下事项必须支持规则化审批：

- 低于 SKU 最低折扣
- 超出代理授信或临时额度
- 已确认订单改价、改数量、改客户或取消
- 负库存、穿透超额或禁止穿透例外
- 盘点差异和库存调整
- 高额采购及采购价格异常
- BOM 版本启用及关键材料变更
- 编号作废、重生产和限量池调整
- 财务红冲、反核销和已结算单据修改
- L4 文件分享和彻底删除
- 历史单证解锁或替换

审批阈值和审批人暂不写死，通过规则表配置。

### 8. 账号与职责分离

- 创建人和审批人原则上不得为同一人，高风险事项必须分离。
- 仓库盘点录入与重大差异审批分离。
- 付款申请、付款执行和核销应按公司实际人员条件尽量分离。
- 系统管理员不能用技术权限代替业务审批。
- 离职或岗位调整时立即停用账号并转移待办和数据归属。
- 禁止多人共用账号。
- 用户级授权不能突破系统中强制执行的职责分离规则；需要例外时必须走高风险授权审批并设置有效期。

### 9. 验收标准

1. 相同页面对不同角色显示正确字段和动作。
2. 无权限用户通过页面、导出和 API 均无法获取受限数据。
3. 跨仓、跨团队和跨客户访问受到数据范围控制。
4. 特价、超授信、库存调整和红冲必须完成审批才生效。
5. 所有授权变更和高风险操作具有审计记录。
6. 用户离职停用后无法登录，原业务数据仍完整保留。
7. 系统管理员无法默认浏览 L4 业务文件内容。
8. 文件分享、导出和批量下载受到独立权限控制。
9. 系统管理员可以给指定人员单独追加或限制权限，且不影响同角色的其他人员。
10. 临时权限到期后自动失效，授权前后权限及授权来源均可审计。

### 10. 待确认事项

- 实际部门、岗位和人员名单
- 每个仓库的操作与主管人员
- 销售客户归属和协作规则
- 特价、授信、采购、盘点和付款审批额度
- 是否存在一人兼任多个岗位及相应补偿控制
- 管理层查看成本和银行资料的具体范围
- 审计角色由谁承担
- 外部货代是否作为受限外部用户登录系统
- 哪些高风险用户级授权需要二次审批，以及临时授权的默认最长有效期

## 第2编｜KAXI_ERP_V1.0_权限注册表_V0.1

> 状态：权限编码基线草案  
> 原则：默认拒绝；页面、API、导入、导出和后台代办使用同一权限服务；系统管理员可为任何人员单独授权，但不能绕过高风险审批。

### 1. 风险等级

| 等级 | 含义 | 授权要求 |
|---|---|---|
| R1 | 普通查看/本人操作 | 角色或用户级授权 |
| R2 | 业务新增、编辑和普通处理 | 角色/岗位授权，受数据范围限制 |
| R3 | 审批、金额成本、导出及批量操作 | 明确授权、完整审计，建议定期复核 |
| R4 | 支付、红冲、反结账、L4文件、薪资敏感、权限管理 | 第二人审批、职责分离；临时授权必须有失效期 |

### 2. 权限记录结构

每个权限至少定义：`permission_code`、名称、模块、资源、动作、风险等级、是否可单独授权、是否需要审批、允许的数据范围类型、字段策略、默认角色及互斥权限组。

表格中类似 `resource.read/manage` 的写法仅为节省篇幅，实际注册时必须展开为 `resource.read` 和 `resource.manage` 两个独立原子权限码。

用户最终权限：

```text
角色权限并集
+ 有效用户追加权限
- 用户限制权限
∩ 公司/部门/仓库/客户/渠道/本人等数据范围
∩ 字段权限
∩ 有效期和账号状态
```

显式限制优先于允许。审批资格不等同于数据查看资格。

| 审计与备份 | 审计导出、备份校验报告 | L4 | 系统、审计 | 系统管理员、审计负责人 | 按审计和容灾策略 | 安全销毁 |

> 法定保存年限必须由财务、法务或专业顾问根据公司主体和业务地区确认，表中年限目前用于系统能力规划，不构成法律结论。

### 4. 业务对象关联规则

| 文件类型 | 必须关联 | 可选关联 |
|---|---|---|
| 商品图片/说明书 | SPU或SKU | 材质、包装方案、平台商品 |
| 材质证书 | 材质或SKU | 供应商、采购批次、生产批次 |
| 客户合同 | 客户、合同编号 | 报价、订单、收款计划 |
| 采购合同 | 供应商、采购合同编号 | 采购单、到货批次、付款计划 |
| 质检报告 | 质检单或批次 | SKU、采购、生产、编号产品 |
| 发货照片 | 发货单 | 订单、箱号、物流单号 |
| 外贸单证 | 出运批次 | 订单、客户、箱号、收款记录 |
| 财务回单 | 收款或付款记录 | 客户、供应商、订单、结算单 |

孤立文件允许暂存，但必须进入“待归类”队列，并设置处理期限。

### 5. 版本规则

- 文件更新默认创建新版本，不覆盖旧文件。
- 当前版本只能有一个，历史版本只读。
- 已发送客户、已用于报关或已参与财务结算的版本不得直接删除。
- 替换时必须填写原因；合同、单证和财务文件需记录替换审批。
- 文件内容相同但文件名不同的情况，通过哈希提示重复，不自动删除。
- 结构化单据重新生成的 PDF/文档必须关联生成时的数据版本。

### 6. 分享规则

- 对外分享默认关闭，由授权角色主动创建。
- 分享链接必须设置有效期；L3 文件建议同时设置访问密码。
- L4 文件默认禁止对外分享，例外需审批。
- 可以限制下载，仅允许在线预览。
- 链接可以随时撤销，访问和下载行为必须记录。
- 分享后文件更新时，旧链接默认仍指向原版本，避免收件人看到未经确认的新版本。

### 7. 删除、回收与归档

```text
正常文件
→ 作废/替换
→ 回收站
→ 到期复核
├── 恢复
├── 归档
└── 授权后彻底删除
```

- 普通用户不能彻底删除文件。
- 被有效业务单据引用的文件不能直接进入彻底删除流程。
- 归档文件仍可检索，但可以迁移到低成本存储。
- 彻底删除必须记录审批人、原因、时间和文件哈希。

### 8. 验收用例

1. 商品说明书关联多个 SKU，只保存一份文件本体。
2. 合同新版本上传后，历史版本仍可查看，订单继续关联签署版本。
3. 仓库手机拍摄发货照片，自动关联发货单和操作人。
4. 无财务权限的用户无法搜索或下载银行回单。
5. 外贸业务创建有期限的装箱单分享链接，并可查看访问记录。
6. 删除中的文件进入回收站，文件管理员可恢复。
7. 证书到期前按配置时间提醒负责人。
8. 数据库与对象存储执行一致性检查，能识别缺失和孤立对象。
