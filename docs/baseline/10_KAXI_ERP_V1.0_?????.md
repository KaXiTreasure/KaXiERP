# KAXI ERP V1.0 完成性审计

> 存放位置：`docs/baseline/`

> 文档职责：判定通用代码完成性并规定正式上线仍需提供的证据，不代替业务签字
> 审计日期：2026-08-24
> 审计依据：`01_KAXI_ERP_项目总览与范围基线.md`、`07_KAXI_ERP_全系统产品与开发清单.md`、`08_KAXI_ERP_测试数据与验收用例.md`  
> 判定原则：模型或文档存在不等于功能完成；必须有可调用入口、权限边界、事务/约束及相称验证证据。

## 1. 结论

当前仓库已完成 V1.0 可在无外部账号、无真实企业参数条件下实现的通用产品代码，包括 18 个领域模块、正式 Web 工作台、PostgreSQL 迁移、原子权限、对象存储、后台任务、数据迁移工具和不可变镜像部署资料。

代码质量门通过后，可判定为“通用代码范围完成”；但以下事项必须使用企业真实事实或目标基础设施验证，仓库本身不能伪造完成证据，因此在实际关闭前不得判定“V1.0 已上线”：

- 真实组织、编码、价格、授信、仓储、生产、财务和税务参数确认；
- 淘宝、抖音、TikTok、小红书、物流、支付、财税等真实授权联调；
- 全量历史数据清洗、期初库存/往来/财务余额签字；
- 目标 Linux/NAS 的镜像拉取、MinIO 恢复、PostgreSQL 恢复、回退及灾难演练；
- 真实业务影子运行、岗位培训、七个验收门签字。

## 3. 自动验证基线

每次候选发布至少执行：

```powershell
python -m pytest backend/tests -q
ruff check backend
python backend/manage.py makemigrations --check --dry-run
python backend/manage.py check
python backend/manage.py spectacular --file openapi.yaml --validate
pnpm --dir frontend build
```

验收时还必须执行 `08_KAXI_ERP_测试数据与验收用例.md` 的真实场景、并发、权限、安全、恢复和对账用例；少量单元/契约测试通过不能替代七个业务验收门。

## 4. 上线证据归档要求

正式上线评审必须附：发布 tag、源码 SHA、镜像 digest、SBOM、provenance、迁移清单、OpenAPI、全量测试结果、恢复演练记录、数据核对签字、权限复核记录、性能与安全报告、回退演练结果及业务负责人签字。任一 P0 否决条件未关闭时不得将本文件状态改为“正式交付”。
