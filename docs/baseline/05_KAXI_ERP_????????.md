## 第1编｜KAXI_ERP_财务系统总体设计_V0.1

> 状态：总体设计草案  
> 已确认：完整财务系统；当前主体本位币CNY；支持未来多主体  
> 注意：正式科目、税务和报表口径必须由具备资质或明确授权的财务负责人复核

### 1. 建设目标

KAXI财务系统不复制现有不规范结构，而是建立业务与财务一体化的复式记账体系：

```text
销售/采购/库存/生产/资金业务
            ↓
        会计事件
            ↓
        过账规则
            ↓
        会计凭证
            ↓
    总账/明细账/辅助账
            ↓
        财务报表
```

业务单据是经济事项来源，会计凭证是财务记账依据。两者关联但不能混为同一状态。

### 2. 已确认会计政策基线

#### 2.1 主体和本位币

- 当前内销与外贸属于同一公司主体。
- 当前主体记账本位币为人民币CNY。
- 数据模型支持未来多公司、多账簿和各主体独立本位币。
- 外币业务同时保存原币金额、CNY金额、汇率类型、日期和来源。

#### 2.2 存货成本

- 普通可替代商品：移动加权平均。
- 限量编号、贵金属和高价值不可替代商品：个别计价。
- 生产计划：使用标准成本。
- 财务核算：使用实际材料、人工、制造费用和实际分摊。
- 标准与实际差异：单独记录并按规则处理。
- 库存方式：永续盘存。
- 资产负债表日：支持成本与可变现净值孰低以及跌价准备。

#### 2.3 会计准则与纳税人类型

- 适用会计准则/制度按公司主体配置，不写死为单一类型。
- 纳税人类型按公司主体配置，并允许未来依法调整。
- 配置采用有效期版本：生效日期、失效日期、状态和审批记录。
- 调整只影响生效日后的业务和期间，不追溯覆盖已过账、已结账和已出具报表的数据。
- 会计准则变更可联动科目模板、报表模板、披露项目和会计政策。
- 纳税人类型变更可联动税码、税率适用、价税模式、发票规则和申报接口。
- 系统应在变更前生成影响评估和未完成事项清单。

配置候选值通过主数据维护，例如：

```text
会计制度/准则
├── 企业会计准则
├── 小企业会计准则
└── 未来依法新增的适用制度

纳税人类型
├── 一般纳税人
├── 小规模纳税人
└── 未来依法新增的类型
```

候选值可以扩展，但业务含义、科目和税务规则必须经财务管理员配置并审批，不能只增加一个文本名称。

### 3. 财务模块

```text
财务
├── 会计政策与账簿
├── 会计科目
├── 凭证与过账
├── 应收
├── 应付
├── 资金
├── 存货成本
├── 生产成本
├── 固定资产（范围待细化）
├── 费用与报销（范围待细化）
├── 税务与发票接口
├── 结账与期末处理
├── 合并/多主体（预留）
└── 财务报表与审计
```

### 4. 会计科目体系

#### 4.1 科目属性

每个科目至少包含：

- 科目编码、名称和层级
- 科目类别：资产、负债、所有者权益、成本、损益、共同类（按适用制度）
- 正常余额方向
- 是否允许直接记账
- 是否启用外币核算
- 是否启用数量核算
- 是否需要客户、供应商、SKU、仓库、部门、项目、渠道、国家等辅助核算
- 生效、停用和版本信息

#### 4.2 科目版本

- 科目不得在有历史凭证后无痕改码或删除。
- 科目调整通过停用、映射和新版本处理。
- 报表模板按科目和辅助维度映射。
- 多主体可以使用统一科目模板并允许受控扩展。

### 5. 会计凭证

#### 5.1 凭证状态

```text
草稿
→ 待审核
→ 已审核
→ 已过账
├── 冲销
└── 更正凭证
```

#### 5.2 凭证控制

- 借方合计必须等于贷方合计。
- 过账期间必须开放。
- 分录科目必须可记账且满足辅助核算要求。
- 已过账凭证不得删除、插入分录或直接修改日期、金额、科目和操作人。
- 错误通过冲销和更正凭证处理。
- 同类已记账凭证编号连续且可审计。
- 业务自动生成凭证保留业务单据、会计事件和规则版本。
- 手工凭证需要独立权限和审批。

### 6. 会计事件与自动过账

业务模块不直接拼接借贷分录，而是产生标准会计事件：

| 会计事件 | 典型来源 |
|---|---|
| GOODS_RECEIVED | 采购验收入库 |
| SUPPLIER_INVOICE_RECOGNIZED | 供应商发票/应付确认 |
| INVENTORY_SHIPPED | 销售出库 |
| REVENUE_RECOGNIZED | 控制权转移/收入确认 |
| CUSTOMER_RECEIPT | 客户收款 |
| RECEIPT_ALLOCATED | 收款核销 |
| MATERIAL_ISSUED | 生产领料 |
| PRODUCTION_COMPLETED | 生产完工 |
| INVENTORY_ADJUSTED | 盘点调整 |
| PACKAGING_CONSUMED | 包装物料消耗 |
| FX_REVALUATION | 期末外币重估 |
| SETTLEMENT_CONFIRMED | 平台/货代结算 |
| RETURN_ACCEPTED | 退货验收 |
| REFUND_PAID | 客户退款 |

每种会计事件匹配版本化过账规则，生成凭证前先进入可复核队列。规则改变不影响历史凭证。

### 7. 销售、应收与收入

#### 7.1 三个独立时点

系统必须区分：

1. **订单确认**：商业承诺成立。
2. **应收确认**：企业取得无条件或按合同节点收款的权利。
3. **收入确认**：相关商品或服务的控制权按合同约定转移。

三者可能同日，也可能不同日。

#### 7.2 收入确认策略

不在程序中写死“发货即收入”。建立收入确认策略：

| 策略示例 | 可能适用业务 | 最终使用需确认 |
|---|---|---|
| 发货确认 | 控制权在交承运人时转移的合同 | 按合同/渠道确认 |
| 签收确认 | 控制权在客户收货时转移 | 按合同/渠道确认 |
| 验收确认 | 需客户验收的商品 | 按验收条款确认 |
| 平台结算确认 | 仅用于特殊平台核对，不自动等同会计收入 | 财务确认 |
| 分履约义务确认 | 商品、服务或重大权利组合 | 财务专题确认 |

每个渠道、贸易类型、客户合同或订单可以引用策略。收入确认事件必须保存依据日期、数量、金额、履约义务和规则版本。

#### 7.3 应收

- 支持订单定金、预收款、发货应收、分期应收和尾款。
- 应收包含原币、本位币、到期日、账龄和核销状态。
- 预收款不自动作为收入。
- 部分发货/分批出运按实际确认数量和合同节点处理。
- 退货、折让、退款和平台扣款通过反向业务及会计事件处理。

### 8. 采购、应付与存货

#### 8.1 三个独立时点

1. 采购订单批准。
2. 商品收货/验收并确认存货。
3. 应付确认及供应商发票匹配。

采购订单本身不产生库存和应付。收货、验收、发票和付款状态分开管理。

#### 8.2 三单匹配

```text
采购订单
↕
收货/验收
↕
供应商发票
```

系统检查：

- 数量差异
- 采购价格差异
- 税额差异
- 币种和汇率差异
- 供应商和SKU一致性
- 超采购、无单收货和无单发票

超过容差进入审批或暂估流程。

#### 8.3 暂估

已验收入库但供应商发票未到时，支持暂估应付/存货成本；发票到达后自动冲回或调整差异。具体科目和月末规则由财务确认。

### 9. 存货成本设计

#### 9.1 移动加权平均

采购入库、生产完工及其他增加库存的业务，按照确认的成本更新移动平均单位成本。

```text
新平均成本
=（原库存金额 + 本次入库金额）
÷（原库存数量 + 本次入库数量）
```

退货、调拨、盘点、负库存禁止和成本回补需定义专项规则。

#### 9.2 个别计价

编号型/高价值商品保存单件成本构成：

- 材料成本
- 人工成本
- 制造费用
- 包装成本
- 采购或加工附加费用
- 可归属物流及其他成本

单件发货时结转对应编号的实际成本。

#### 9.3 调拨

- 同一主体仓库间调拨不产生收入和利润。
- 调拨保留原成本，并记录在途状态和物流费用。
- 跨主体调拨未来按内部交易处理，不能沿用同主体调拨逻辑。

#### 9.4 跌价准备

支持：

- SKU/批次/编号层面的可变现净值评估
- 跌价准备计提、转回和结转
- 评估依据、审批及附件
- 财务报表披露所需数据

### 10. 生产成本

#### 10.1 成本对象

生产订单或生产批次作为成本对象，归集：

- 直接材料
- 直接人工
- 制造费用
- 委外加工
- 包装成本
- 正常损耗
- 异常损耗

#### 10.2 标准与实际

- 标准成本用于预算、生产建议和差异分析。
- 实际成本用于正式核算。
- 材料价格差异、用量差异、人工差异和制造费用差异分开记录。
- 正常损耗按确认政策进入产品成本；异常损耗单独计入损益或责任分析。

### 11. 包装、物流和外贸成本

#### 11.1 包装成本

- 预包装：完成时归集实际包装材料和作业成本。
- 发货现场包装：发货或封箱时归集。
- 拆包：可退材料恢复库存，不可退部分计入损耗。

#### 11.2 外贸和履约费用

可归集：

- 国内段运输
- 国际运费
- 保险费
- 报关费
- 货代服务费
- 认证/单证费用
- 平台佣金和支付手续费
- 公司承担的关税及履约费用

费用先归集到订单或出运批次，再按配置方法分摊至订单行/SKU：重量、体积、数量、货值或人工比例。分摊方法和结果必须可追溯。

### 12. 外币核算

- 交易初始确认使用交易日即期汇率，或经财务批准的合理近似汇率。
- 外币货币性项目在资产负债表日按期末即期汇率重估。
- 汇兑差额进入当期损益或按适用准则处理。
- 历史成本计量的外币非货币性项目保持交易日折算金额。
- 汇率来源、日期、类型、人工调整和批准人全部留痕。

### 13. 会计期间与结账

```text
期间开放
→ 预结账检查
→ 成本计算
→ 外币重估
→ 暂估与摊销
→ 对账
→ 结转损益
→ 期间关闭
```

结账检查包括：

- 未过账会计事件
- 不平衡或异常凭证
- 负库存和库存金额异常
- 收货未暂估/发票未匹配
- 未核销资金
- 未完成平台/货代结算
- 外币未重估
- 成本未计算或待调整
- 应收应付与总账不一致

反结账必须审批、记录原因和影响范围；重新结账前重新执行检查。

### 14. 辅助核算

凭证行可按科目要求携带：

- 客户
- 供应商
- 员工
- 部门
- 仓库
- SKU/商品分类
- 项目
- 销售渠道
- 贸易类型
- 国家/地区
- 订单
- 出运批次
- 生产订单
- 平台/货代

辅助核算维度必须结构化，不能全部塞入凭证摘要或JSON。

### 15. 财务报表

V1.0包括：

- 总账
- 明细账
- 科目余额表
- 试算平衡表
- 辅助核算余额和明细
- 应收应付账龄
- 资产负债表
- 利润表
- 现金流量表
- 库存成本及跌价
- 生产成本和差异
- 外币余额及汇兑损益
- 渠道、客户、国家和SKU经营利润

法定报表与管理报表分开定义，避免管理口径改变法定账簿。

### 16. 会计档案和审计

- 凭证、账簿、报表和原始凭证进入会计档案分类。
- 已过账凭证不可删除或直接修改。
- 会计数据必须提供标准导出能力。
- 文件版本、业务单据、会计事件、凭证和报表可双向追溯。
- 操作日志按人员、时间、内容查询和导出。
- 电子资料具备完整性校验、备份、归档和恢复能力。
- 会计档案保留期限按现行法规和财务负责人确认结果配置。

### 17. 财务权限与内控

需要分离：

- 单据创建与审批
- 凭证制单、审核和过账
- 付款申请、付款执行和核销
- 盘点差异录入和审批
- 汇率维护和复核
- 反结账申请和批准
- 科目/过账规则维护和启用

系统管理员可配置权限，但不能绕过财务审批或默认读取银行及L4财务文件。

3. 国内各渠道收入控制权转移点。

5. 应收和应付具体确认时点。
6. 供应商发票、暂估和差异容差。

11. 电子发票、税务申报和银行接口。
12. 会计档案保留期限和审批人。

### 20. 官方依据

- 财政部《企业会计准则第1号——存货》：允许先进先出、加权平均或个别计价，并要求性质和用途相似的存货采用一致方法；已售存货成本结转损益；期末按成本与可变现净值孰低计量。
- 财政部《企业会计准则第14号——收入》：收入确认围绕合同、履约义务及商品控制权转移设计。
- 财政部《企业会计准则第19号——外币折算》：外币交易折算为记账本位币，期末对外币货币性项目重估并处理汇兑差额。
- 财政部《会计信息化工作规范》及《会计软件基本功能和服务规范》：会计软件需支持凭证、账簿、报表、数据接口、档案、日志、备份和已记账资料保护。

## 第2编｜KAXI_ERP_会计科目模板_V0.1

> 状态：核心科目模板草案  
> 说明：系统同时维护企业会计准则与小企业会计准则模板；正式启用由公司主体会计政策决定

### 1. 模板原则

- 科目模板按会计准则/制度、版本和生效日期管理。
- 企业选择准则后复制并形成主体科目表，不直接修改系统标准模板。
- 主体可以在不违反适用规定的前提下增加明细科目和辅助核算。
- 不存在的交易可不启用对应科目，但保留未来启用能力。
- 科目编号是业务配置，不作为数据库主键。

## 第3编｜KAXI_ERP_收入确认策略矩阵_V0.1

> 状态：政策配置草案  
> 核心原则：订单、收款、发货、应收和收入分别记录；收入依据合同履约及控制权转移

### 1. 策略匹配维度

系统按优先级匹配收入确认政策：

```text
客户合同特例
→ 客户+贸易类型
→ 渠道+贸易类型
→ Incoterm+运输方式
→ 公司默认政策
```

每条策略保存版本、有效期、财务审批和必要证据。

### 2. 核心状态分离

| 状态维度 | 示例 |
|---|---|
| 订单状态 | 已确认、部分发货、已完成 |
| 履约状态 | 未履约、部分履约、履约完成 |
| 收款状态 | 未收、预收、部分收、已收清 |
| 应收状态 | 未生成、部分应收、到期、已核销 |
| 收入状态 | 未确认、部分确认、全部确认、已冲销 |
| 税务/开票状态 | 未开票、部分开票、已开票、红冲 |

这些状态不得相互替代。例如已收款不必然等于已确认收入。

### 3. 内销平台订单

#### 3.1 候选政策

| 场景 | 建议触发点 | 必要证据 | 备注 |
|---|---|---|---|
| 普通已支付平台订单 | 按平台规则、合同及控制权转移点配置 | 发货、物流签收或平台完成状态 | 不统一写死 |
| 平台存在无理由退货期 | 根据控制权、退货权及可靠估计配置 | 平台完成、退货期及历史退货数据 | 财务确认政策 |
| 平台先结算后发货 | 不能仅因到账确认收入 | 履约证据 | 到账先记预收/平台资金 |
| 部分退款 | 按退款和退货事实冲减 | 平台退款单、退货验收 | 保留原收入链路 |

#### 3.2 数据要求

- 平台订单状态
- 支付时间和金额
- 发货及签收时间
- 平台确认完成时间
- 退款和退货状态
- 平台结算期间
- 收入政策版本

### 4. 国内代理订单

| 场景 | 建议触发点 | 应收处理 |
|---|---|---|
| 普通代理销售 | 合同约定控制权转移点 | 按账期生成应收 |
| 客户自提 | 客户签收/提货确认 | 提货时或合同节点 |
| 需要验收 | 验收通过 | 验收前保持发出商品/合同资产状态 |
| 预收款销售 | 控制权转移时确认收入 | 收款先记合同负债/预收 |
| 授信销售 | 控制权转移并满足收款权利条件 | 转应收，授信占用转应收风险 |

### 5. 国内私域订单

私域必须选择标准合同/交易条款，不能因为来自企业微信或朋友圈就跳过收入政策。

推荐至少区分：

- 已付款快递
- 货到付款
- 线下自提
- 企业账期
- 定制及预售

### 6. 一般贸易出口

#### 6.1 Incoterms不是唯一判断

贸易术语、合同条款、运输安排、客户验收和风险/控制权实际转移共同决定收入确认点。系统不单凭FOB、CIF、DDP文字自动确认收入，而是由财务批准的策略映射。

#### 6.2 候选策略

| 业务条款 | 候选触发点 | 证据 |
|---|---|---|
| EXW/客户提货 | 交付客户或其指定承运人 | 提货单、签收、交接记录 |
| FOB类 | 按合同和装运责任确定 | 报关、装船/交承运人文件 |
| CIF/CFR类 | 按合同判断控制权转移，不等同费用承担期 | 商业发票、提单、交运记录 |
| DDP/DAP类 | 可能接近目的地交付 | 目的地签收、清关和交付证据 |
| 客户验收条款 | 验收通过或符合准则的其他时点 | 客户验收文件 |
| 分批出运 | 每批独立评估已履约数量 | 出运批次及单证 |

具体策略必须由财务结合标准合同模板确认。

### 7. 跨境电商

| 场景 | 候选触发点 | 证据 |
|---|---|---|
| 国内直发海外消费者 | 平台/合同控制权转移点 | 国际物流、签收、平台完成 |
| 海外仓销售 | 消费者订单履约，而非国内调拨至海外仓 | 海外仓出库、末端签收 |
| 平台托管履约 | 根据平台协议和控制权判断 | 平台履约及结算数据 |
| 拒收/退运 | 按退货和可回收商品处理 | 物流异常、退运、入库处置 |

发往自有或受控海外仓通常属于库存地点转移，不自动确认销售收入。

### 8. 预售、定制和穿透订单

- 收到定金：记录预收/合同负债，不自动确认收入。
- 生产中：记录在制品和合同履约状态。
- 穿透库存：只是供应承诺，不产生收入。
- 指定编号锁定：只是库存/履约占用，不产生收入。
- 完成并达到控制权转移条件后确认收入及结转成本。

### 9. 包装、服务和赠品

订单包含以下内容时，需要判断是否构成单独履约义务：

- 定制包装
- 维护套件
- 延保或售后服务
- 赠品
- 指定编号服务
- 设计或定制服务

系统支持将订单总交易价格按财务批准的方法分配到履约义务。普通促销赠品和重大权利的具体政策待财务确认。

### 10. 收入确认记录

每次收入确认保存：

- 公司和账簿
- 客户、订单和订单行
- 履约义务
- 确认数量
- 原币收入、税额和CNY金额
- 收入确认日期
- 策略和版本
- 触发事件
- 控制权转移证据
- 出运/物流/验收关联
- 会计事件和凭证
- 后续冲销或调整链

### 11. 应收触发策略

应收与收入策略分别配置：

| 付款安排 | 应收候选节点 |
|---|---|
| 下单即付 | 收款前可无应收，到账记预收或直接核销应收 |
| 定金+尾款 | 按付款计划生成应收/合同权利 |
| 发货后账期 | 发货或满足合同收款条件时生成应收 |
| 验收后付款 | 验收后生成无条件应收 |
| 平台结算 | 平台交易明细生成平台应收，结算单核销 |

系统区分合同资产与无条件应收的能力；具体科目随会计准则和政策模板配置。

### 12. 收入冲销和调整

- 退货、退款、折让和取消使用反向会计事件。
- 不删除原收入确认记录。
- 部分退货按订单行、数量和原确认批次冲减。
- 外币退货按政策记录原始汇率、退款汇率和汇兑差异。
- 已结账期间的调整进入允许期间或经审批反结账。

### 13. 策略验收场景

1. 平台已收款但未发货，不提前确认收入。
2. 国内代理分批发货，收入和成本按已履约部分处理。
3. 外贸定金到账，只形成预收/合同负债。
4. 外贸一单多批出运，每批保存独立确认证据。
5. 发往海外仓不确认销售，消费者订单履约后再确认。
6. 客户验收不通过，不按原计划确认全部收入。
7. 部分退货准确冲减原收入、税额、成本和应收。
8. 策略版本变化不影响历史收入记录。

- 税务开票时点与会计收入差异处理

### 15. 结论

KAXI不使用单一“发货即收入”规则。收入确认由财务批准的版本化策略决定，策略根据渠道、贸易类型、合同、Incoterm和客户特例匹配，并保存控制权转移证据。

### 16. 财务数据约束

6. 科目停用不影响历史查询，但不能用于新凭证。
7. 辅助核算必填维度由科目定义并在过账前校验。
8. 外币分录同时保存原币和本位币金额。
9. 余额表可以从已过账分录重建并核对一致。
10. 会计准则、纳税人类型和政策版本有效期不得重叠。

## 第5编｜KAXI_ERP_业务事件与凭证映射_V0.1

> 状态：过账规则草案  
> 说明：科目名称为逻辑科目，正式科目编码在会计准则及科目模板确认后确定

### 1. 设计原则

- 业务状态与会计状态分离。
- 所有自动凭证来源于版本化会计事件。
- 过账规则按公司、账簿、会计政策、贸易类型和有效期配置。
- 已过账凭证不因规则变化而改写。
- 表中分录仅为首版典型逻辑，税额、暂估和特殊合同需按实际业务拆分。

### 2. 采购与库存

#### 2.1 采购验收入库且成本已确定

| 借/贷 | 逻辑科目 | 辅助核算 |
|---|---|---|
| 借 | 库存商品/原材料 | SKU、仓库、供应商、采购单 |
| 借 | 可抵扣进项税（适用时） | 税码、供应商、发票 |
| 贷 | 应付账款/暂估应付 | 供应商、采购单 |

#### 2.2 已入库但发票未到

| 借/贷 | 逻辑科目 |
|---|---|
| 借 | 库存商品/原材料 |
| 贷 | 暂估应付 |

发票到达后冲回暂估并按实际发票确认应付和税额差异。

#### 2.3 采购退货

按原入库/应付关系生成反向会计事件；不得删除原入库凭证。

### 3. 销售与收入

#### 3.1 收到客户预付款

| 借/贷 | 逻辑科目 | 辅助核算 |
|---|---|---|
| 借 | 银行存款/平台资金 | 银行账户、币种 |
| 贷 | 合同负债/预收款 | 客户、订单 |

预付款不自动确认为收入。

#### 3.2 达到收入确认条件

| 借/贷 | 逻辑科目 | 辅助核算 |
|---|---|---|
| 借 | 应收账款/合同资产/预收冲抵 | 客户、订单、出运批次 |
| 贷 | 主营业务收入 | SKU、渠道、贸易类型、国家 |
| 贷 | 销项税（适用时） | 税码 |

具体借方取决于收款权利和预收余额；系统依据政策生成，不固定一种分录。

#### 3.3 结转销售成本

| 借/贷 | 逻辑科目 | 辅助核算 |
|---|---|---|
| 借 | 主营业务成本 | SKU、订单、渠道 |
| 贷 | 库存商品 | SKU、仓库、编号 |

成本结转事件与收入事件可以关联，但具体时点由政策确定。

#### 3.4 销售退货/折让

- 退货验收恢复合格库存时，按原成本或核准成本恢复。
- 收入、税额和应收通过反向事件处理。
- 商品进入异常库存时，不直接恢复正常可售成本状态。

### 4. 收款与核销

#### 4.1 客户收款

| 借/贷 | 逻辑科目 |
|---|---|
| 借 | 银行存款/平台资金 |
| 贷 | 应收账款或预收款 |

#### 4.2 外币核销差异

根据应收初始汇率与收款实际汇率产生汇兑收益或损失，原币余额与本位币差额分别记录。

### 5. 付款与应付

#### 5.1 供应商付款

| 借/贷 | 逻辑科目 |
|---|---|
| 借 | 应付账款/预付账款 |
| 贷 | 银行存款 |

银行手续费单独计入财务费用或适用成本对象。

### 6. 生产

#### 6.1 生产领料

| 借/贷 | 逻辑科目 |
|---|---|
| 借 | 生产成本—直接材料 |
| 贷 | 原材料/半成品 |

#### 6.2 人工与制造费用归集

| 借/贷 | 逻辑科目 |
|---|---|
| 借 | 生产成本—直接人工/制造费用 |
| 贷 | 应付职工薪酬/制造费用归集科目 |

#### 6.3 生产完工

| 借/贷 | 逻辑科目 |
|---|---|
| 借 | 库存商品/产成品 |
| 贷 | 生产成本—材料/人工/制造费用 |

#### 6.4 异常损耗

异常损耗不默认进入合格产品成本，按审批政策计入损失、责任往来或其他指定科目。

### 7. 预包装

#### 7.1 包装材料消耗

根据包装是否构成产品成本或履约费用，借记包装成本、库存商品附加成本或销售费用，贷记包装物料。

#### 7.2 拆包

可退材料恢复包装物料库存；不可退材料进入包装损耗。原预包装成本记录通过反向事件调整。

### 8. 仓库与盘点

#### 8.1 同主体仓库调拨

不确认收入和利润。可通过库存明细维度转移；发生的运输费用按政策计入库存成本或期间费用。

#### 8.2 盘盈盘亏

- 盘盈：借记库存，贷记待处理财产损溢或核准科目。
- 盘亏：借记待处理财产损溢或核准科目，贷记库存。
- 批准处置后转入责任人往来、费用或损失。

### 9. 平台与货代结算

#### 9.1 平台结算

平台销售收入、退款、佣金、广告费、支付手续费和实际到账分项核对，不允许只按净到账确认收入。

#### 9.2 货代结算

货款代收、运费、报关、服务费、其他扣款和公司实际到账分别记账，并关联订单/出运批次。

### 10. 外贸费用

国际运费、保险、报关和认证等费用先归集到出运批次，再按确认方法分摊至订单/SKU；承担方不是公司时不计入公司成本，但保留业务记录。

### 11. 期末处理

#### 11.1 外币重估

对外币货币性资产和负债按期末汇率重估，差额进入汇兑损益或适用科目。

#### 11.2 存货跌价

| 借/贷 | 逻辑科目 |
|---|---|
| 借 | 资产减值损失 |
| 贷 | 存货跌价准备 |

转回和已售存货对应准备结转使用独立事件。

#### 11.3 损益结转

期间关闭前将损益类科目按配置结转至本年利润，生成系统结转凭证。

### 12. 规则验收

1. 每个业务事件只生成一套有效凭证。
2. 所有凭证借贷平衡。
3. 业务单据、会计事件、凭证和附件可双向追溯。
4. 过账规则变化不修改历史凭证。
5. 外币分录原币和CNY金额可核对。
6. 库存数量账与财务库存金额账可以对账。
7. 应收应付子账与总账一致。
8. 平台和货代按毛额、费用和净额完整对账。
9. 已结账期间不能新增普通凭证。
10. 冲销和反核销完整保留原始链路。

### 13. 待确认

- 正式科目编码和科目模板
- 收入确认策略及各渠道控制权转移点
- 应收、应付和税额的具体确认节点
- 暂估和发票差异处理
- 生产人工及制造费用分配
- 包装成本资本化或费用化规则
- 平台、货代和国际费用科目及分摊规则
- 固定资产、工资、费用报销和税务事件

## 第6编｜KAXI_ERP_财务外围模块总体设计_V0.1

> 状态：需求与架构基线草案  
> 范围：应收、应付、费用报销、固定资产、薪资、税务与发票  
> 适用前提：当前单一公司主体、CNY 本位币；数据模型预留多主体、多账簿及多币种

### 1. 总体原则

1. 业务单据、结算单据、会计事件和会计凭证分层保存，不以一张表混合状态。
2. 总账是正式会计记录；各子模块是明细子账，已过账数据只能冲销或更正，不能直接删除。
3. 每笔子账余额必须能够追溯到业务单据、合同、发票、收付款、会计事件和凭证。
4. 应收、应付、收入、成本、收付款、开票及纳税状态相互独立，不能用一个“已完成”状态替代。
5. 会计准则、纳税人类型、税码、科目映射和过账规则均按公司及有效期版本化。
6. 系统管理员可以给任何人员单独授权，但财务敏感操作仍受职责分离、审批和审计约束。

### 2. 应收账款

#### 2.1 范围

- 平台订单、代理订单、私域订单、一般贸易出口、跨境电商及其他销售应收。
- 订金、预收款、阶段应收、尾款、押金、平台待结算款、货代代收款。
- 贷项、折让、退款、坏账准备、核销、外币重估及汇兑差额。
- 代理授信额度、已占用额度、逾期额度和临时授信。

#### 2.2 核心状态

```text
应收项目：草稿 → 已确认 → 部分核销 → 已核销
                    ├→ 逾期
                    ├→ 争议
                    └→ 已冲销/坏账处理

收款单：草稿 → 待认领 → 已确认 → 部分分配 → 已分配
                                      └→ 已退款/已冲销
```

#### 2.3 控制规则

- 应收确认策略与收入确认策略分离，可按合同约定在发货、签收、验收、里程碑或其他节点触发。
- 收款必须先形成资金流水，再按客户、订单、应收项目进行核销；不明收款进入待认领池。
- 支持一款多单、一单多款、部分核销、跨币种核销和预收转应收。
- 外币应收同时保存原币、入账汇率、CNY 金额、核销汇率及汇兑损益。
- 授信检查在订单批准或库存承诺前执行；超额必须走有期限、有金额的例外审批。
- 坏账准备与实际核销分开，核销后保留追偿台账。

### 3. 应付账款

#### 3.1 范围

- 供应商采购、委外加工、物流、货代、报关、保险、平台及其他服务应付。
- 采购预付款、暂估应付、供应商发票应付、付款计划、扣款、贷项及退款。
- 国内采购发票、境外单据和无票业务的合规标识。

#### 3.2 核心状态

```text
应付项目：草稿 → 已确认 → 部分核销 → 已核销
                    ├→ 暂估
                    ├→ 争议/冻结
                    └→ 已冲销

付款申请：草稿 → 待审批 → 已批准 → 待支付 → 已支付 → 已核销
                                      └→ 驳回/撤销
```

#### 3.3 三单匹配

采购订单、验收入库、供应商发票分别记录。系统比较数量、含税/未税价格、税额、币种、汇率、供应商及 SKU；差异在容差内自动通过，超差进入审批。已收货未收到发票时按政策暂估，发票到达后冲回暂估并记录差异。

付款申请、付款审批、支付执行及付款核销应由不同权限控制。供应商银行账户变更须二次复核，支付文件生成和银行回单导入全程留痕。

### 4. 费用与报销

#### 4.1 业务类型

- 员工报销、借款、还款、差旅申请、对公费用申请、公司卡消费。
- 国内差旅、海外差旅、招待、办公、市场推广、平台广告、物流及其他费用。
- 可归集至部门、员工、项目、订单、SKU、客户、渠道、国家、出运批次或生产成本对象。

#### 4.2 流程

```text
事前申请（按政策需要）
→ 借款/预支（可选）
→ 费用单及票据采集
→ 政策校验
→ 业务审批
→ 财务复核
→ 生成应付员工/供应商
→ 支付与核销
→ 归档
```

#### 4.3 控制规则

- 费用政策按公司、费用类型、职级、地区、币种和有效期版本化。
- 重复发票、重复金额日期、超标准、缺附件、跨期和预算超额自动预警。
- OCR 只用于辅助录入，原始影像、人工修订及校验结果必须保留。
- 费用资本化、存货成本化、生产归集或期间费用化由规则和财务复核决定。
- 私人付款账户与员工档案关联；敏感账户信息加密并限制导出。

### 5. 固定资产

#### 5.1 范围

- 资产类别、资产卡片、在建转固、购置、领用、调拨、维修、改良、减值、盘点及处置。
- 多部门、多地点、多责任人和多资金来源管理。
- 会计折旧与税务折旧分别计算，保留差异台账。

#### 5.2 生命周期

```text
在建/待验收 → 已验收待启用 → 使用中
                           ├→ 闲置
                           ├→ 维修/改良
                           ├→ 减值
                           └→ 处置中 → 已处置
```

#### 5.3 核算规则

- 资产类别配置资本化门槛、预计寿命、残值率、折旧方法、折旧科目和辅助维度。
- 默认支持直线法，同时保留工作量法等扩展能力；正式启用参数由财务批准。
- 折旧按期间批量试算、复核、过账；已过账折旧通过调整事件处理。
- 改良支出区分资本化和费用化，处置计算收入、税额、账面净值及处置损益。
- 资产盘点可使用标签/二维码，差异必须审批后生成会计事件。

### 6. 薪资与职工薪酬

#### 6.1 系统边界

V1.0 包含薪资核算、计提、发放、成本归集和总账集成。考勤可由 ERP 录入或外部导入；个税申报、社保公积金缴纳通过标准导出/接口衔接，不在未经授权时直接代替法定申报平台。

#### 6.2 数据与流程

- 薪资期间、薪资组、工资项、计算规则、员工银行账户和成本归属。
- 应发工资、奖金、补贴、加班、请假扣款、社保、公积金、个税及其他代扣。
- 计算草稿 → 复核 → 锁定 → 计提过账 → 发放 → 银行核对 → 归档。
- 生产人员工资可归集至生产订单/批次，管理及销售人员工资归集至相应部门和费用科目。

#### 6.3 隐私与内控

- 薪资、身份证件、银行账户及个税数据按最高敏感级控制和加密。
- 薪资制表、审核、支付及系统权限管理分离。
- 普通系统管理员不默认获得薪资明细读取权；单独授权必须有审批、期限和审计记录。

### 7. 税务与发票

#### 7.1 税务主数据

- 公司纳税人类型及有效期版本。
- 税种、税码、税率、征收方式、价税模式、适用地域和生效日期。
- 客户/供应商开票资料、商品税收分类映射、免税/零税率/不征税依据。
- 国内销售、出口、跨境平台及进口业务税务场景。

#### 7.2 发票管理

```text
销项：开票申请 → 校验 → 待开具 → 已开具 → 已交付
                                      ├→ 红冲申请 → 已红冲
                                      └→ 作废（仅合法状态下）

进项：采集 → 查验/校验 → 业务匹配 → 财务确认 → 抵扣/不抵扣处理 → 归档
```

- 发票状态不决定收入状态；未开票收入和预开票业务均可依法、按政策独立处理。
- 发票号码、代码、开票方、购买方、金额、税额及原始文件建立重复校验。
- 红字发票必须引用原发票和对应退货、折让或更正依据。
- 电子发票原件、版式文件、结构化数据、查验结果及签名/哈希统一归档。

#### 7.3 申报边界

系统形成销项、进项、未开票、出口及税额差异台账，支持申报底稿、勾稽检查和标准导出。正式直连税务平台前必须单独进行接口合规、安全评估和授权；税率及申报规则不得硬编码。

### 10. 权限与职责分离

- 应收维护、授信审批、收款认领和核销分离。
- 供应商维护、采购、付款申请、付款审批、支付执行和核销分离。
- 报销申请人不能审批自己的单据；财务复核不能被普通流程管理员绕过。
- 资产卡片维护、盘点录入、差异审批及处置审批分离。
- 薪资计算、复核、支付和数据导出分离。
- 税码维护、开票、红冲、申报底稿确认和凭证审核分离。
- 个人单独授权记录授权人、原因、权限范围、公司/数据范围、生效期和失效期；高风险权限自动触发复核。

### 11. 月结阻断检查

- 应收应付子账与总账不一致。
- 未认领大额收付款、长期未核销预收预付。
- 到期未处理应收、异常授信、应计未计坏账准备。
- 已收货未暂估、发票未匹配、付款未核销。
- 已批准未入账费用、借款长期未冲销。
- 资产未转固、折旧未计提、处置未完成。
- 薪资未计提或计提与发放不一致。
- 发票、税额与业务台账差异未解释。

阻断项和预警项由财务策略配置；强制放行必须记录批准人、原因和影响。

### 12. V1.0 验收标准

1. 六类子模块均能完成从业务申请到凭证及归档的闭环。
2. 任一子账余额可以向下穿透至单据和附件，向上核对至总账及报表。
3. 支持部分结算、预收预付、暂估、冲销、更正、多币种和跨期控制。
4. 已过账及已结账历史不可被配置变化覆盖。
5. 关键职责分离、单独授权、敏感数据保护和完整审计日志有效。
6. 税率、会计政策、费用政策、折旧政策和过账规则均可版本化调整。

### 13. 待由实施阶段录入的企业参数

以下不阻塞总体设计，但必须在上线初始化时由授权财务负责人确认：

- 首次启用的会计准则、纳税人类型及具体税种。
- 资产资本化金额门槛、类别寿命、残值率及折旧方法。
- 费用标准、审批金额层级和预算控制方式。
- 薪资项目、社保公积金所在地规则及成本分配方式。
- 三单匹配容差、暂估政策、账龄区间及坏账政策。
- 开票平台、银行、税务及薪资外部接口的实际可用范围。

## 第7编｜KAXI_ERP_财务外围数据对象清单_V0.1

> 目的：作为数据库详细设计和 API 清单的输入；字段均默认包含公司、创建/修改人、时间戳、状态、版本号和审计信息。

### 1. 应收与收款

| 数据对象 | 用途 | 关键约束 |
|---|---|---|
| `receivable_item` | 应收项目子账 | 原币及 CNY 金额；余额不得小于零；关联确认策略 |
| `receivable_schedule` | 分期/到期计划 | 各期合计等于应收项目金额 |
| `customer_receipt` | 客户收款流水 | 银行/平台流水号防重；未认领可入池 |
| `receipt_allocation` | 收款核销 | 核销金额不得超过收款可用额和应收余额 |
| `customer_credit_profile` | 客户授信版本 | 额度、币种、有效期、审批和冻结状态 |
| `credit_exposure` | 授信占用明细 | 可由订单、应收及逾期明细重建 |
| `bad_debt_assessment` | 坏账评估 | 政策版本、账龄、预期损失率和审批证据 |

### 2. 应付与付款

| 数据对象 | 用途 | 关键约束 |
|---|---|---|
| `payable_item` | 应付项目子账 | 区分暂估、发票和其他应付；原币/CNY 双金额 |
| `payable_schedule` | 付款计划 | 到期日、优先级、冻结及折扣条件 |
| `supplier_invoice` | 供应商发票 | 号码、开票方、金额税额组合防重 |

### 8. 数据库实现约束

1. 金额统一使用 `NUMERIC(20,6)`，汇率使用 `NUMERIC(20,10)`，不得使用浮点数。
2. 所有正式业务表必须包含 `company_id`；账务表同时包含 `ledger_id` 和会计期间。
3. 业务编号在公司与单据类型范围内唯一，外部流水采用来源系统与外部编号联合唯一。
4. 状态迁移由服务层命令控制，禁止普通更新接口直接写任意状态。
5. 核销、分摊、折旧、工资及税额的明细合计采用数据库约束与事务内校验双重保护。
6. 已过账记录使用不可变控制；更正以反向记录和新版本实现。
7. 身份、银行、薪资和税务敏感字段加密；日志不得记录完整明文。
8. 文件只在对象存储保存，数据库保存文件 ID、哈希、版本、分类和关联关系。
9. 高频余额可设置汇总表，但必须能从不可变明细重新构建并核对。
10. 会计、税务及业务政策均保存命中版本，确保历史可重演。
