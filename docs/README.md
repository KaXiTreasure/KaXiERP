## 冲突处理顺序

1. `09` 中最新且明确标记“已确认”的决策。
2. `01` 的范围基线与需求追踪。
3. `02–06` 专题设计。
4. `07–08` 实施和验收清单。
5. `00` 的进度描述与 `10` 的完成性证据。
6. Git 历史中的旧稿和仍标记“待确认”的建议。

发现冲突时，先在 `09` 增加决策，再同步受影响的现行文档和测试。
